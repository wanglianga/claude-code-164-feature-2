# 市民篮球场 · 预约拼场 / 照明计费 / 冲突调解（移动端 H5 演示）

一个面向**手机现场操作**的单页应用：市民按场地、半场/全场、时间段、人数、是否拼场、是否需要夜间照明预约公共篮球场；队长邀请队员签到、散客申请拼场；管理员在后台看到每个时段的预约人数、实际到场、支付状态与冲突风险；社区工作人员处理噪声投诉、未成年人夜留与篮筐争议。**预约全场但实际人数不足时，系统自动提示队长三选一（接受拼场 / 降为半场 / 补缴全场差额），队长拒绝且超过保留时间，管理员可释放一个半场给候补散客，并重新生成两组人的场地边界、照明费用分摊与结束提醒、由双方确认。** 所有费用变化、退款补偿、处罚记录都与具体规则条文（编号 R-xxx）一一关联、可点击查看。

技术栈：**Vue 3 + TypeScript + Vite + Naive UI**，纯前端 + 内置 mock 数据与响应式规则引擎，无需后端即可完整演示全部流程。

## 本地启动

```bash
npm install
npm run dev        # http://localhost:5173 （已监听 0.0.0.0，手机局域网可访问）
```

其他命令：

```bash
npm run build      # vue-tsc 类型检查 + 生产构建到 dist/
npm run preview    # 预览生产构建
npm run typecheck  # 仅类型检查
npm run smoke      # 规则引擎冒烟断言（esbuild 打包后在 Node 执行，无需浏览器）
```

### Docker 一键启动（推荐用于演示）

```bash
docker compose up -d --build     # 构建并在后台启动
# 打开 http://localhost:8080
docker compose logs -f web       # 查看日志
docker compose down              # 停止
```

多阶段 `Dockerfile`（Node 构建 → nginx 提供静态文件）与 `docker-compose.yml`、`nginx.conf` 已内置；容器仅托管打包后的前端，数据仍为页面内 mock。

建议用浏览器 DevTools 切换到手机视口（如 iPhone 390×844）体验；页面最大宽度 480px 居中。

## 建议的验证路径（均为可在页面上实际操作的流程）

1. **预约**：场地预约 → 选择 B区/河滨球场 → 半场/全场、时段（已满/故障/维修的半场自动禁用）、人数（低于建议下限会提示拼场）、勾选接受拼场与夜间照明 → 看到押金与预估费用 → 提交后在「我的队伍」出现签到码。
2. **队长签到与照明计费**：我的队伍 → B001 晨光队 → 邀请队员、逐个签到；推进时钟，观察"还能打多久"、照明分钟数、实时金额（拼场 8 折、按签到人数平摊）；点「结束使用并关灯」按实际时长结算，押金余额退还。
3. **散客拼场**：切到王同学 → 拼场签到页对晨光队的申请显示"待处理"；切回队长**同意**后散客可凭码签到；也可找其他队伍新申请，队长拒绝时必须填写正当理由，否则产生 20 元资源占用费与信用扣分。
4. **迟到 / 爽约 / 超时**：B002 散客联队预置了迟到 23 分钟与无理由拒拼扣费；把时钟推过某待开场场次开场 20 分钟，看板/后台出现「释放场地」（R-LATE-1）；对进行中场次持续推时过 20:05 可见超时费 2 元/分钟、超 15 分钟可强制清场（R-OT-2）；B006 是已结算的超时案例。
5. **照明故障（I-005）**：事件页 → B区 H1 故障工单 → 管理员核验后由队伍三选一：等维修 / 改约（押金全退、优先排位）/ 全额退款，费用计时此前已自动冻结（R-LIGHT-3）。
6. **下雨地滑 / 篮筐维修**：后台「场地状态控制」可发布积水暂停/湿滑/恢复（R-WX-1）；B005 预置了篮筐紧急维修改约 + 5 元交通补偿案例（R-WX-2）；I-002 是已裁决的争抢篮筐工单（R-DISPUTE-1）。
7. **噪声投诉 / 未成年人夜留**：以社区工作人员身份处理 I-001（首次劝导 vs 24h 内第 2 次核实收 50 元，R-NOISE-1）、I-004（监护人接回登记，R-MINOR-1）。
8. **封场（I-006）**：管理员对河滨 H3/H4 的社区活动工单签发封场令 → 仅受影响的 B009 被中止、押金全退、可免费改约；同场地正在打球的 B003（H1/H2）不受影响；场地页/看板对应半场显示"封停"（R-SEAL-1）。
9. **现场看板**：任意身份都能看到每个半场当前使用者、签到码、到场人数、剩余/超时时间，以及争议时"预约码→时段比对→先到先得+信用分"的判断指引。
10. **公平性解释**：管理后台有黄金时段固定队 ≤60% 的配额条；规则页顶部给出改约优先级链（安全维修 > 已支付已签到 > 固定队 > 先到先得 > 信用分），每张被改约卡片（B005/B009 等）都有管理员说明与规则编号，解释"为什么是这一方被改约/限制"（R-FAIR-1~4）。
11. **全场人数不足自动调整（本次新增，B011 猎鹰队）**：切队长 → 我的队伍顶部出现橙色调整卡：河滨 H3/H4 全场只到 4 人，候补 2 组散客，保留期倒计时（19:30 提示，至 19:45）。
    - 队长可 **①接受拼场**（候补 3+2 人加入同一全场、照明 8 折按人均摊）／**②降为半场**（选保留 H3/H4，全场押金 100→半场 50、差额退回，照明分段重算）／**③坚持包场**（取消 8 折、按全场 2 半场原价续用，展示至结束的补缴差额），也可**拒绝**。
    - 用顶部时钟 `+10分` 推过 19:45，或点"拒绝"后再推过保留期 → 切管理员，后台「全场人数不足·自动调整」专区出现红色「释放一个半场给候补」；选保留侧与承接候补（王同学）后执行：原队缩为保留半场、信用 -2（不记爽约），新建散客半场预约承接空半场，照明按分界时间分段（此前全场 8 折、此后各付半场），**费用重算明细与投诉/申诉入口同步双方**（事件页自动生成"释放半场"工单）。
    - 释放后切队长/散客/看板：均可看到**重新生成的中线场地边界（各占一个篮筐）、照明分摊、结束前 10 分钟提醒**；队长与散客分别点"确认边界与照明分摊"，管理员专区实时显示**双方是否都确认**，未确认前不得占用对方半场。
    - 队长可在调整卡或工单中 **24 小时内申诉**，管理员在事件页**复核裁决**并同步双方（R-MERGE-3）。

## 已执行的验证

- `npm run build`（含 `vue-tsc --noEmit` 全量类型检查）通过，产物输出到 `dist/`。
- 所有 `.vue` 单文件组件通过 `@vue/compiler-sfc` 模板解析校验。
- `npm run dev` 启动后，用 `curl` 验证首页（HTTP 200、标题正确）以及全部 `src/**` 模块（含新增 `AdjustPanel.vue`、调整后的各页面/引擎/store/mock/rules）经 Vite 转换后均返回 200。
- 规则引擎冒烟测试 **49 项断言全部通过**（`npm run smoke`，esbuild 打包后在 Node 执行 `src/store.ts + src/lib/engine.ts`），除既有的照明实时计费、无理由拒拼、押金结算、爽约释放、照明故障、封场局部生效外，重点覆盖全场人数不足自动调整全链路：
  - B011 全场仅 4 人触发提示，19:42 保留期剩 3 分钟不可释放、19:45 届满可释放，识别 2 组候补；
  - 三选一：接受拼场（候补 3+2 人并入同一全场）、降为半场（押金 100→50、退 50 差额、scope/halves 收缩）、坚持包场（分界后全场 2 半场原价、取消 8 折，19:52 时 62.40+20.00=82.40 元）；
  - 拒绝且超保留期→管理员释放半场：原队缩半场、信用 100→98、散客新建半场预约且 3 人签到、候补申请置为 `assigned`、自动生成关联双方的 `halfRelease` 工单（R-MERGE-3/4）；
  - 释放后照明分段（分界前全场 8 折、分界后半场自付），双方分别确认后状态置 `confirmed`；
  - 队长申诉写入工单并转处理中、管理员复核裁决后办结；
  - 降半场队伍结束结算：39 分全场 62.40 + 10 分半场 8 折 8.00 = 70.40 元，押金 50 不足、需补缴 20.40 元。
- Docker：已提供多阶段 `Dockerfile`、`docker-compose.yml`、`nginx.conf` 与 `.dockerignore`。当前沙箱环境无可用 Docker 守护进程，未实际执行镜像构建；在装有 Docker 的机器上执行 `docker compose up -d --build` 后访问 `http://localhost:8080` 即可（构建步骤与本地 `npm run build` 相同）。
